## 一、论文原配代码审计

### 代码溯源

从 GitHub 原始 PGDiff 代码 (`inference_pgdiff.py`) 确认基线行为：

```python
# 原论文 partial_guidance 函数签名
def partial_guidance(x, t, ..., s_start=1, s_end=0.7):
    # s_start / s_end 在本函数体内从未被引用
    with th.enable_grad():
        fake_g_output = restorer(x, y_t=y, t=t).clamp(-1,1)
        fake_g_output = fake_g_output.detach().requires_grad_(True).cuda()
        mse_loss = F.mse_loss(fake_g_output, pred_xstart_in, reduction='sum')
        gradient = th.autograd.grad(total_loss, pred_xstart_in)[0]
```

### 原论文 p_sample_loop 中的引导调用 (gaussian_diffusion.py:442-466)

```python
# 每个时间步:
out["mean"] = self.condition_mean(cond_fn, out, x, t, model_kwargs=model_kwargs)

# s_start/s_end 仅在 while N-1>0 (多步引导 N>1) 时检查:
while N - 1 > 0:               # N=1 默认 → 整个 block 跳过
    if t < s_start and t > s_end:  # 从未执行
```

### 结论：论文原配实际行为

| 参数 | 论文代码的实际行为 |
|------|-------------------|
| N | 1（默认），引导在每个时间步都执行 |
| s_start / s_end | **死参数**。N=1 时在采样循环中不生效，partial_guidance 内部也未使用 |
| Restorer 调用 | **每个时间步都调用**（共 1000 次） |
| Loss | MSE |
| 梯度缩放 | 无 schedule。梯度直接为 `d(MSE)/d(pred_xstart)` |
| Restorer 位置 | `enable_grad` 内部调用，但 `.detach()` 断开 → 等价于 BLOCK_UNET_GRAD 行为（但浪费 VRAM） |

**之前报告的错误：** 首次 paper_baseline 测出 V2=2.9457, Sharp=25.2，是因为未设置 `CONSTANT_SCHEDULE=True`，autoresearch train.py 默认的 linear schedule (`0.3 + 0.7 * t/T`) 削弱了梯度。修正后正确值为 V2=2.7874, Sharp=23.7。

## 三、每项改动的诚实评估

### ✅ 真实有效

| 改动 | 贡献 | 机制 |
|------|------|------|
| **S_END=0.5 + early_stop** | Sharp +13% | 引导减半 → 扩散模型自由演化更多步 → 自然锐度释放 |
| **BLOCK_UNET_GRAD=True** | VRAM -77%, 质量零影响 | restorer 前向移出 autograd 图，梯度流向相同 |
| **K=2 + scale=0.20** | RC 再 -50%, 指标持平④ | 稀疏引导 + 尺度补偿，等价质量下更少 restorer 调用 |

### ⚠️ 需要进一步拆解

| 改动 | 贡献 | 说明 |
|------|------|------|
| **Huber loss vs MSE** | Sharp 可能的部分贡献 | 当前消融中与 Linear Schedule 捆绑测试，未独立验证 |
| **Linear Schedule (0.3+0.7*t/T)** | Sharp 可能的主要贡献 | 早期引导强（schedule≈1.0）、晚期弱（schedule≈0.3），强化了"早期锁结构、晚期释放扩散"的分工 |

### ✗ 无效方向

DDPM 步数缩减、DPM-Solver、Sobel 边缘损失、梯度动量、Restorer EMA 平滑、分析梯度、DDIM、Hybrid 采样——全部无效或有害。

## 四、V2 指标的批判性评估

### 公式

```
V2 = SSIM(output, LQ_input) × naturalness × clip(sharpness_gain, 0.2, 5.0)
```

### 缺陷

1. **SSIM 以退化输入为参照。** 修复的目标是输出与退化输入不同。SSIM 越高 = 修复越少 → V2 奖励"不做修复"。
2. **Naturalness 恒为 0.865-0.867。** CV < 0.001，无判别力。
3. **GAIN ≥ 5.0 时 V2 退化为 `SSIM × 4.33`。** 95% 有效实验在此区间，GAIN 的判别力丧失。
4. **PGDiff 论文使用 PSNR/SSIM-to-GT, LPIPS, FID, NIQE, ArcFace 等**——均以高清真值或身份特征为参照。本项目无配对 GT 数据，这些指标不可直接计算。

### 可用无参考指标

Sharpness (Laplacian variance) 和 Edge Density 是两类可靠的客观无参考指标。ArcFace 身份相似度（输出 vs LQ输入）是待引入的关键身份保持指标。

## 五、关键结论

1. **论文原配**: N=1 时 s_start/s_end 是死参数，引导在每个时间步（共 1000 次）都执行。无 linear schedule。V2=2.7874, Sharp=23.7。

2. **S_END=0.5 + early_stop 是最大单项改进**: Sharp +13%, RC -50%。机制是减少过度引导，让扩散模型有 500 步自由演化空间释放天然锐度。

3. **BLOCK_UNET_GRAD 是零代价工程优化**: 质量与③完全相同，VRAM 从 ~4000MB 降至 1018MB。

4. **最终推荐配置 ⑤ (K=2, scale=0.20, S_END=0.5, BLOCK_UNET_GRAD=True, Huber)**: 相对于论文原配 Sharp +42%, RC -75%, Time -43%。

5. **消融尚不完整**: Huber loss 与 Linear Schedule 的独立贡献未拆解。这是下一步需要完成的验证。

6. **V2 不应用作优化目标。** 后续实验应使用 Sharpness、Edge Density、以及待引入的 ArcFace 身份相似度作为评估指标。
